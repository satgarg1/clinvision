Revenue / No-shows filter row — layout options

The pill toggle, single-day date+Today, Period dropdown, and From/To fields all sit in one row above the table. Two live complaints: too much vertical air between the search box and this row, and the pill/date/Today still don't read as aligned with each other.

Root cause of both: From/To are the only controls with a label stacked above them ("From" / "To"). Every other control (the pill, the Date field, Today, the Period dropdown) has no label — so lining any of them up against a labelled From/To column means either matching box-centers (pill floats too high) or padding the label-less ones out with an invisible spacer (which is what shipped last — technically aligned, but it also added the exact dead space now being flagged). Every option below removes that mismatch at the source: nothing in the row stacks a label above a control anymore, so a plain align-items: center aligns everything correctly with no spacer, and the row goes back to one line's worth of height.

1Tag-in-pill

Recommended

"From"/"To" become small uppercase tags built into the left edge of the same pill-shaped field, instead of a separate label sitting above it — one control, one line, same shape language as the rest of the row. Reads clearly even to someone who's never seen the page before, and costs almost nothing to build (a CSS-only change to the existing field, no new component).

2Unified range pill

Most compact

Period dropdown and both From/To fields collapse into one control: a single pill showing "12 Aug – 19 Aug" that opens one calendar for picking both ends (click a start day, then an end day, same popover). Cuts three controls down to one — the least horizontal space of any option, and nothing to align since there's only one field left. Needs a genuinely new dual-date calendar view, not just a style tweak, so it's more build effort than the others.

3Side label

Smallest code change

Same "From"/"To" wording as today, just moved from above the field to beside it — a small grey word, then the field, all on one line. Closest to the current markup (the label stays a real, separate element — just `flex-direction: row` instead of `column`), so this is the least code to change if the goal is a minimal diff.

4Position-only

Not recommended here

Drop the words "From"/"To" entirely — first field is always the start, second is always the end, separated by an arrow. The most compact option on paper, but it trades away the one explicit cue reception staff have for which field is which, and this clinic's own front desk skews toward lower app-fluency staff who currently rely on that label — a bad trade for the little extra space it saves. Included for completeness, not a real contender.
